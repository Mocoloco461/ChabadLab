# הצעדים הבאים: מעבר לשרת עם GPU

המסמך הזה מיועד לסשן או לסוכן שממשיך את העבודה על מנוע החיפוש באגרות קודש בשרת חדש עם GPU.
כל ההיסטוריה המלאה, כולל מספרים, נמצאת ב-`WORKLOG.md` בשורש הריפו.
הודעת פתיחה מוכנה להדבקה בסשן חדש נמצאת ב-[`HANDOFF_PROMPT.md`](HANDOFF_PROMPT.md).

---

> **עדכון (17.11.2026, שרת GPU):** צעד A הושלם. ההגדרה Qwen3-Embedding-4B + e5-large, עם כוונון מחדש, נותנת **89.9% בסט הראשי ו-88.9% בסט האימות**, ועברית→יידיש עלתה ל-84% / 88%. הפרטים ב-`WORKLOG.md`. **צעד B (reranker) הושלם:** ‏bge-reranker-v2-m3 על 50 האגרות הראשונות נותן **95.1% בסט הראשי ו-90.8% בסט האימות**. **הבא בתור:** צעד D (שיפורים קטנים), ואז שלב 3 (קטגוריות), שדורש אישור. הטבלה שלמטה היא המצב שלפני המעבר.

* סינונים: כרך, שנה עברית ולועזית, חודש, שפה, נמען, מספר אגרת.

## 2. הקמה בשרת החדש

```bash
git clone https://github.com/Mocoloco461/ChabadLab && cd ChabadLab && git checkout igrot-kodesh

# סביבה: torch עם CUDA (לא גרסת ה-CPU)
uv venv .venv && source .venv/bin/activate
uv pip install torch --index-url https://download.pytorch.org/whl/cu124   # להתאים לגרסת ה-CUDA (nvidia-smi)
uv pip install -r search-site/requirements.txt httpx
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"

# אינדקס טקסט (כ-25 שניות; search-site/data/ לא נמצא ב-git)
python search-site/build_index.py

# אינדקס סמנטי: --device auto בוחר cuda לבד ומריץ fp16
python search-site/build_embeddings.py --model BAAI/bge-m3 --batch 64
python search-site/build_embeddings.py --model intfloat/multilingual-e5-small --batch 128   # בסיס להשוואה

# שרת
cd search-site/app && uvicorn server:app --host 0.0.0.0 --port 8765
```
**הערות:**
* השרת בוחר אוטומטית את המודל החזק ביותר שהבנייה שלו הסתיימה: bge-m3, אחר כך e5-base, אחר כך e5-small. אפשר לכפות מודל עם `IGROT_EMB=search-site/data/emb/<slug>`. המשתנה `IGROT_DEVICE` קובע את המכשיר (ברירת מחדל: cuda אם יש).
* **דיסק:** כל מודל דורש כמה GB במטמון של HuggingFace. בשרת הקודם הדיסק התמלא. כדאי לבדוק `df -h` לפני הורדות.
* **התקנת `optimum`** הורידה את גרסת `huggingface_hub` ושברה את sentence-transformers. אם צריך אותה, להתקין אחריה גם `httpx`.

## 3. צעדים לפי סדר עדיפות

### צעד A: מודל הטמעה חזק (הכי חשוב)

1. בונים את bge-m3 על GPU ומריצים את שני הסטים:
   ```bash
   python search-site/eval/run_eval.py --label "bge-m3 GPU"
   python search-site/eval/run_eval.py --cases search-site/eval/holdout/holdout1.jsonl --label "HOLDOUT bge-m3 GPU"
   ```
2. משווים עוד כמה מודלים רב-לשוניים, ובוחרים לפי **סט האימות**:
   * `intfloat/multilingual-e5-large`
   * `intfloat/multilingual-e5-large-instruct`
   * `Alibaba-NLP/gte-multilingual-base`
   * `Qwen/Qwen3-Embedding-0.6B` / `4B` (אם יש מספיק זיכרון ב-GPU)

   **לפני הבנייה:** אם המודל דורש קידומת לשאילתה או לקטע (instruction prefix), מוסיפים אותה ל-`PREFIXES` ב-`build_embeddings.py`.
3. **כוונון מחדש לכל מודל:**
   ```bash
   python search-site/eval/tune_hybrid.py   --emb search-site/data/emb/<slug>
   python search-site/eval/tune_semantic.py --emb search-site/data/emb/<slug>
   ```
   * מעדכנים את `HYBRID_K / HYBRID_W_TEXT / HYBRID_W_SEM` ואת `SEM_LEX_W / SEM_K` ב-`app/search.py`.
   * **בודקים על סט האימות** (`CASES=search-site/eval/holdout/*.jsonl`) לפני שמקבלים שינוי.
   * עם מודל טוב יותר, ייתכן שמשקל הטקסט צריך לרדת.

### צעד B: מדרג מחדש (reranker, cross-encoder)

* `BAAI/bge-reranker-v2-m3`, או reranker רב-לשוני של Qwen3, מדרג מחדש את 50–100 התוצאות המובילות של המצב המשולב או מצב המשמעות.
* על GPU זה לוקח עשרות מילישניות. בדרך כלל זה השיפור הגדול ביותר לשאלות ולתיאורים במילים אחרות.
* **מימוש:**
  * שלב אחרי `hybrid_search` / `semantic_search` ב-`app/search.py`.
  * הקלט: השאילתה + הקטע הטוב ביותר של כל אגרת (`best_chunk`), או 2 הקטעים הטובים.
  * מאפשרים להדליק ולכבות את השלב עם משתנה סביבה.
  * מודדים אותו כמו כל שינוי אחר.

### צעד C: עברית→יידיש (crosslang, כרגע כ-16%)

* קודם בודקים כמה bge-m3 ו-reranker משפרים.
* אם עדיין חלש: מתרגמים את השאילתה ליידיש עם LLM (Claude Haiku, או LLM מקומי על ה-GPU), ומריצים את החיפוש גם על התרגום.

### צעד D: שיפורים קטנים שנשארו מהמשוב

הדוחות המלאים נמצאים ב-`eval/feedback/`.
* **"האם התכוונת":** שגיאת כתיב במילה היחידה המשמעותית מחזירה 0 תוצאות. פתרון: אינדקס טריגרמים או מרחק עריכה על אוצר המילים.
* **התאמה לנמען:** חיפוש שם בטקסט יעדיף אגרות שהנמען שלהן הוא האדם הזה. היום משקל עמודת הנמען ב-bm25 הוא 3.0. אפשר להוסיף שכבה בדירוג.
* **צורה מדויקת במילים קצרות:** במילים כמו "ים" ו"לב" התוצאות מעורבבות עם צורות עם תחיליות (בים, כלב).
* **מצב משולב:** מתעלם מ-`sort` ומוגבל ל-300 תוצאות.
* **נתונים:**
  * `date_editorial` מכיל בכמה מכתבים טקסט שאינו תאריך ("רוסית | תרגום חפשי")
  * באגרת צז שורת התאריך היא `תשג"ה`, כנראה טעות במקור
  * ל-395 אגרות מתוארכות אין תאריך לועזי

## 4. שלב 3: נושאים וקטגוריות (עוד לא התחיל, דורש אישור של המשתמש)

**האסטרטגיה שסוכמה עם המשתמש:**
1. **רשימת קטגוריות:** LLM קורא מדגם של כמה מאות אגרות ומציע 30–50 נושאים. **המשתמש מאשר ומתקן את הרשימה.**
2. **סיווג כל האגרות.** לכל אגרת:
   * 1–3 קטגוריות
   * סיכום של שורה אחת
   * מילות מפתח
   * **מיקום הנמען** (עיר/מדינה)

   המיקום חשוב: שדה `city` הוא העיר שממנה הרבי כתב, כמעט תמיד ברוקלין. מיקום הנמען נמצא לפעמים ב-`recipient_note`.
3. בדיקה של מדגם ידני.

**אפשרויות למודל הסיווג:**

| אפשרות | עלות | הערות |
|---|---|---|
| Claude Haiku 5.5 עם Batch API | בערך 2–4$ ל-11 אלף אגרות | צריך מפתח API |
| Claude Sonnet 5.5 | בערך 30–60$ | מדויק יותר |
| LLM מקומי על ה-GPU | חינם | איכות העברית הרבנית נמוכה יותר. אפשר להשוות על מדגם |

**מימוש:**
* טבלה `letter_meta` (או עמודות חדשות) ב-`search.db`.
* סינון לפי קטגוריה ואזור בממשק.
* לבנות את הטבלה מקובץ JSONL שנשמר בריפו (לא רק ב-`data/`).

**מפתח API:** לא להדביק בצ'אט. מגדירים כסוד בהגדרות הסביבה.

## 5. שלב 4: סוכן AI עם RAG (עוד לא התחיל)

* **endpoint:** `/api/ask`. סוכן Claude (Sonnet 5.5 / Opus 5.5) עם כלים:
  * `text_search`
  * `semantic_search` (או המצב המשולב)
  * `get_letter`
  * סינונים וקטגוריות
* **תשובות:** מבוססות רק על האגרות. כל טענה מגיעה עם הפניה: כרך, מספר אגרת וקישור. אם אין מקורות, הסוכן אומר את זה.
* **ממשק:** לשונית "שאל את האגרות".
* **בדיקה:** סט שאלות שהתשובה עליהן ידועה, ושופט (LLM או אדם) שבודק נכונות וציטוטים.

## 6. תהליך העבודה (להמשיך באותה שיטה)

* **כל שינוי:** קוד, ואז הרצת `run_eval.py` על **שני הסטים**, ואז רשומה ב-`WORKLOG.md`: מה נעשה, קומיט, תועלת במספרים, הערות להמשך.
* **אסור לכוונן על סט האימות.** אם הוא "נשרף" אחרי הרבה סבבים, מבקשים מסוכן לכתוב סט אימות חדש:
  * `eval/sample_letters.py` עם seed חדש
  * הוראות כמו ב-holdout1
* **סוכני בדיקה:** סוכני Sonnet שבודקים את ה-API ואת הממשק, כמו בסבב 1. הדוחות נשמרים ב-`eval/feedback/<name>_roundN.md`.
* **הפעלה מחדש של השרת:** `search-site/scripts/restart_server.sh`. **לא** להשתמש ב-`pkill -f`: זה הורג גם את ה-shell שמריץ את הפקודה.
